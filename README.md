 Что пошло не так (и как это было решено)

В ходе выполнения лабораторной работы возникли следующие технические сложности, которые помогли глубже понять механизмы безопасности Linux:

1.  **SUID-бит не работал на копии bash без ключа `-p`.**  
    При запуске `~/demobash -c 'id'` эффективный UID оставался равным реальному (`euid=1000`), несмотря на установленный SUID-бит. Это связано с тем, что современные версии bash из соображений безопасности принудительно сбрасывают привилегии при обнаружении несоответствия реального и эффективного UID.  
    *Решение:* Использовать ключ `-p` (preserve privileges): `~/demobash -p -c 'id'`. Этот флаг явно указывает интерпретатору не сбрасывать `euid`, что позволило продемонстрировать механизм повышения привилегий.

2.  **ACL не давал доступ к файлу, даже если права на сам файл были выданы.**  
    После добавления правила `setfacl -m u:student2:r ~/secret.txt` пользователь `student2` всё равно получал ошибку «Отказано в доступе». Проблема была в правах родительского каталога `/home/riki`, который имел права `750` и запрещал вход другим пользователям. Без бита `x` на каталоге ядро не позволяет пройти путь к файлу, независимо от ACL на самом файле.  
    *Решение:* Временно добавить право на проход через каталог: `chmod o+x ~`. Для постоянного решения лучше переместить общие файлы в отдельную директорию с корректными правами.

3.  **Ошибка «Permission denied» при создании правил sudo через конвейер.**  
    Попытка записать правило напрямую через `echo "..." | sudo tee /etc/sudoers.d/file` иногда приводила к ошибкам прав или некорректному формату, если команда выполнялась не из-под root. Кроме того, прямое редактирование без проверки синтаксиса рискованно.  
    *Решение:* Всегда использовать `sudo visudo -f /etc/sudoers.d/student2-lab`. Утилита `visudo` автоматически проверяет синтаксис перед сохранением и предотвращает блокировку системы из-за опечаток в конфигурации sudo.

4.  **Опечатка в имени файла при проверке снятия SUID-бита.**  
    При попытке проверить права после `chmod u-s` была допущена опечатка в имени файла (`demobas` вместо `demobash`), что вызвало ошибку «Нет такого файла».  
    *Решение:* Использовать автодополнение клавишей Tab для избежания ошибок ввода имён файлов при работе с системными утилитами.
